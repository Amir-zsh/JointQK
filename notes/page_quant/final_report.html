The question

Spend unequal bits on unequal tokens, in page-sized blocks

The proposal: quantize keys in 64-token pages — the unit paged-attention servers already use — and, inside each page, give more precision to the tokens that future queries will actually attend, predicted from the calibrated query distribution.

Two separable claims live inside it: a format claim (fixed-byte pages are the right container) and an allocation claim (importance-driven per-token precision beats uniform treatment). Both proved true. The decisive economics turned out to hide in a third question nobody asked at the start: what representation goes inside the page.

How we kept ourselves honest

Pre-registered grids, success bars, and interpretation rules before any downstream number existed. Hyperparameters frozen on calibration-side rows with a git-stamped audit file. Blocking probes (rate honesty with every sideband charged, sink preservation, norm preservation) that a codec must pass before spending GPU-hours on benchmarks — these caught six real bugs at probe cost. Every comparison is a row-paired bootstrap, not a difference of two averages.

How the method works

From raw keys to compressed pages, step by step

The intuition first

When a transformer reads a long document, it stores a key — a 128-number fingerprint — for every token it has seen. Each future token compares its query against all stored keys to decide where to pay attention. On an 8-billion- parameter model reading a 30k-token prompt, this key cache alone runs to gigabytes, and it is the main thing limiting how much context fits on a GPU.

Our method shrinks each key from 256 bytes to roughly 16–32 bytes, using three ideas that stack:

Idea 1 — store keys in the coordinate system queries actually use. Raw key coordinates are the wrong units: some directions matter enormously to attention scores, others barely at all. From a few hundred sample prompts we learn, for every attention head, a rotation into a basis where "error in the stored key" is exactly "error in the attention score." Compressing in that basis means every bit we spend buys attention fidelity, not generic numerical fidelity. (Think of JPEG: it doesn't compress raw pixels, it first transforms the image into components the eye cares about unequally.)

Idea 2 — spend bits where attention will look. Inside every 64-token page, a handful of tokens will receive nearly all future attention (8 of 64 typically carry ~43% of it). A cheap signal computed from the key itself predicts which ones. Each token then gets its own precision level — the important few get fine quantization, the ignored many get coarse — chosen so the whole page still fits an exact, fixed byte budget. The choice is written in 2–3 bits per token; nothing else needs transmitting.

Idea 3 — do all the work once, while reading the prompt. Compression happens as the prompt is processed. The cache then holds the reconstructed keys, so the generation loop — the latency-critical part — touches no compression machinery whatsoever. The compact encoded pages are what you keep for cheap storage tiers: CPU offload, prefix caches, parked sessions.

Each step in detail

STEP 1

Calibration — learn how this model attends

ONCE PER MODEL

Run the unmodified model over ~400 representative prompts (≈4.4M tokens) and record, for each of the 31×8 (layer, head) pairs, three statistics: the average query μ̄_q, the query spread Σ_Q (a 128×128 matrix saying which directions queries probe hard), and the key spread Σ_K.

Operations
ordinary forward passes with capture hooks; streaming averages — no training, no gradients.
Cost
~30 minutes on 4 GPUs; output is one 84 MB statistics bundle (raw captures can be deleted).
Repeats?
Only when the model changes. Measured bonus: the statistics are stable across tasks and even into generation, so one calibration serves broadly.
STEP 2

Fit the codec — turn statistics into lookup tables

ONCE PER MODEL

From the statistics, build everything compression will need, per (layer, head):

  1. The rotation F (and its inverse): the basis where squared storage error equals attention-score error — so the quantizer's plain "minimize squared error" objective automatically optimizes what the model cares about.
  2. Step sizes: one base quantization step, solved by bisection so the average rate lands exactly on target, plus a ladder of coarser/finer multiples — the precision levels tokens will choose among.
  3. Frozen code tables for the entropy coder: which quantized values occur, how often. Freezing them on calibration data is what makes reported compression rates honest on unseen text.
  4. The importance direction μ̄_q, kept so compression can score tokens later with a single dot product.
Cost
15–25 minutes, one GPU; output is one bundle file (~90–260 MB) that serves every compression rate — the byte budget is chosen at run time.
Repeats?
Only with the model or a deliberate re-calibration.
STEP 3

Compress at prefill — once per prompt

ONCE PER PROMPT

As the model finishes reading the prompt, each (layer, head)'s keys pass through the codec:

  1. Rotate every key into the learned basis (one 128×128 multiply per key) and take its norm (stored as one fp16 number — this is what makes the rare, extreme "attention sink" tokens safe to quantize).
  2. Cut the token stream into 64-token pages, each with an exact byte budget (e.g. 1,536 bytes at 1.5 bits/coordinate — every page identical, which is what a paged-attention block allocator wants).
  3. Score importance: one dot product per token against μ̄_q. (Enabled when running at tight budgets — the regime where it wins; positions 0–3, the attention sinks, always get maximum precision regardless.)
  4. Assign each token a precision level by cost/benefit within the page: a fast bisection finds the price-per-bit at which the page exactly fills its budget; important tokens buy fine steps, ignored tokens accept coarse ones. The outcome is just a 3-bit label per token.
  5. Quantize and entropy-code the rotated coordinates with the frozen tables; pack labels + codes into the page bytes.
  6. Write the reconstructed keys back into the cache (decompress immediately, once). The encoded pages are kept if a storage tier wants them.
Cost
<0.1% of prefill compute — roughly 1–2 s of overhead on a 16k-token prompt whose prefill already takes ~4–6 s. Runs once, never again for that prompt.
Output
cache: reconstructed keys (attention-ready) · pages: 16–24 bytes per token per head, vs 256 uncompressed.
STEP 4

Generation — deliberately empty

PER TOKEN: NOTHING

Every generated token runs attention against the reconstructed keys exactly as if no compression existed: no unpacking, no entropy decode, no custom kernel. This is the design's answer to "isn't entropy coding too slow?" — we measured that decoding the whole context per token would take ~1.8 s at 64k context, ~300× over budget, so the architecture guarantees it never happens. New keys produced during generation stay in fp16 (they are few).

STEP 5

Cold tiers — where the encoded pages earn their keep

ON TIER TRANSITIONS

When a session is parked, a prefix cached, or memory pressure pushes the cache to CPU/NVMe, it's the compact pages that move — 8–16× less traffic. On resume they are entropy-decoded once, and even our unoptimized decoder is faster than the PCIe transfer it shortens. Fixed page sizes mean the storage allocator handles them like any other block.

Cost summary in one line: ~50 GPU-minutes once per model · <0.1% of prefill once per prompt · zero per generated token · one-shot decode only when a cache crosses a storage tier.

FINDING 1 / 5

The tokens that matter are not the ones theory pointed at

Importance must be predictable from the key alone. The textbook signal fails on Llama — and the intuitive one points backwards:

candidate signalrank corr. with realized attentionverdict
Q-weighted energy kᵀΣ_Q k−0.78 ANTI-PREDICTS
textbook Expected Attention≈ 0 USELESS
calibrated mean logit μ̄_qᵀk/√d+0.73 … +0.82 PREDICTS

High-energy keys are logit repellers — pushed deep into negative scores, where softmax gradients vanish and huge quantization error is harmless. The attended tokens are found by the humble mean-logit signal (~85% top-decile capture, transfers out of distribution). Context for everything that follows: the first four tokens (attention sinks) carry 19–84% of attention per head; inside a typical page, 8 of 64 tokens carry ~43% of its mass.

The subtle half of the finding: plain rate-distortion-optimal allocation actively takes bits away from attended tokens (they are expensive). Importance weighting isn't a bonus on top of RDO — it is the correction RDO needs.

FINDING 2 / 5

Importance-weighted allocation works — precisely when rate is scarce

Implementation: per-token choice among quantizer rungs inside each fixed-byte page, distortion weighted by ω from the mean-logit signal. The decoder reads only 2–3-bit rung labels — ω costs nothing to transmit. Replicated across three quantizer families:

contexteffect of ω on F1statistics
entropy-coded rungs @1.0 bits+2.9 (musique +5.8) SIG
scalar direction codes @1.0 bits+3.7 (hotpotqa +8.6) SIG
fine-grained vector quantizer @1.0−1.0 TIE
entropy-coded rungs @1.5 bits−1.6 (lcc −2.4) lcc SIG
The regime law: ω pays exactly when the rate ladder is coarse enough that unweighted allocation starves attended tokens. Fine ladders self-protect; abundant rate leaves nothing to rescue; and on out-of-distribution code (lcc) — where the predictor is weakest — misdirected ω does mild harm. That last edge resisted a gating fix and stays open.

FINDING 3 / 5

Fixed-byte pages — the serving format — are free

At 1.5 bits/coord, the entropy-coded quantizer confined to fixed 64-token pages scores 43.98 (trio mean) vs 43.02 unconstrained — every task a statistical tie, ≈1 point under full precision, at 10.7× compression. The page constraint costs ~1% of distortion in oracle terms. And per-token allocation is what makes fixed pages work: a page-uniform scheme strands 18% of the byte budget; per-token allocation fills 99.6%.

FINDING 4 / 5

Entropy decode is 300× too slow for generation — and never needs to run there

Measured on our CUDA rANS decoder: 1.2–1.5 Gsym/s (the entropy kernel is just ~10% of wall time). A resident compressed cache must re-decode the whole context per generated token: at 64k that is ~2 billion symbols → ~1.8 s per token against a ~5 ms attention budget. Parallelism isn't the obstacle — 4 million independent lanes exist; the per-token re-decode architecture is. Entropy streams also can't be randomly accessed, so fusing decode into the attention kernel is structurally impossible.

Resolution: in the deployed pattern, decode speed never matters. Compression runs once at prefill (<0.1% of prefill compute); the cache stores reconstructions; generation reads plain tensors. Entropy decode runs only on tier transitions — offload restore, prefix-cache load — where it is faster than the PCIe transfer it shortens.

FINDING 5 / 5

The entropy-free frontier: mapped, then closed

A cache that stays compressed while resident needs a random-access codec. Nine design iterations pursued one; the probes caught every failure before it cost GPU-hours, and the final answer is quantitative.

The graveyard: three failures invisible to accuracy proxies

No zero level. Mid-rise grids inflate every near-zero coordinate to ±s/2 — all key norms grow coherently, generation collapses to whitespace, while top-1 ranking metrics look fine (uniform inflation cancels in rankings).

Quantiles are not tails. Scales covering the 99.9th percentile still clip the attention sinks, which sit 2.7–5.4× beyond it and carry most attention. Sink mass fell 0.84 → 0.007; every proxy stayed calm. Sinks need explicit handling — per-token norms plus an absolute ±1 direction grid (legal because directions are unit vectors) — and positions 0–3 forced to maximum precision.

Sink directions are outliers too. One level deeper: codebooks trained on 138k bulk tokens have no codewords near sink directions. Caught by the sink-mass gate at probe cost, zero GPU-hours wasted.

The final test: is the VQ gap data-starvation or physics?

Pre-registered: retrain the residual-VQ codebooks on 5× the calibration tokens (a fresh 40-row train-split capture) and re-bench one config. Result: 42.62 → 42.06 — a wash. The gap is the entropy model over coordinate values — fundamental at these rates. Reopening this door requires a different idea class (learned transforms with lattice/trellis codes); the exact bar to clear is now on record.
