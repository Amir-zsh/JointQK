All served evals now run through a declarative layer: one JSON spec per study is the single source of truth for every argument, and every run leaves a provenance manifest sufficient to reproduce it exactly. Nothing method- or cell-specific is hardcoded in the runner anymore.

3TurboQuant-INT2: implemented, corrected, measured

What was wrong. Two independent defects. First, the documented recipe (SGLANG_LLOYD_MAX=1 on the int2plain path) pointed at a flag only the mixed OSCAR pool read — the plain pool serving QuaRot/Naive/TurboQuant ignored it, so "TurboQuant" would have silently been QuaRot mislabeled. Second, the legacy LM encoding (LM_RATIO=1.16, fitted to the old clip path's dynamic range) costs +26% distortion vs exact Lloyd-Max.

The fix. An LM branch in both plain-pool writers — the fused-Hadamard decode writer and the plain writer that prefill uses for pre-rotated K/V (the two-writer split is the same bug class as the VQ-V prefix-dequant). Indices come from LM thresholds on per-(token, head) standardized coords; the stored (scale, zero) encode the MSE-optimal uniform-level fit to the LM centroids (Δ* = 0.98774σ), so every reader keeps the untouched (q−zero)·scale contract — the exact-centroid dequant path with its documented decode instability stays off. Cost of the uniform-level compromise: +1.2% vs exact LM analytically, +0.8% on real post-FWHT Llama K/V (derivation + Monte-Carlo + real-data table: pipelines/oscar_e2e/turbo_lm_check.py).

Exact quantizer semantics (if you apply by hand)

# per (token, head), on the POST-rotation bf16-roundtripped row v[0..D):
mean = Σv/D;  std = sqrt(Σ(v-mean)²/D + 1e-8)
q_i  = (d_i >= -T·std) + (d_i >= 0) + (d_i >= T·std)     # d = v - mean
       T        = 0.9810652732849121                       # LM threshold
scale = DELTA · std;   zero = 1.5 - mean/scale
       DELTA    = 0.9877367723552428                       # = E[x·l(x)]/E[l(x)²], x~N(0,1)
# readers stay untouched: k_hat = (q - zero) * scale  ==  (q-1.5)·DELTA·std + mean

Why uniform levels instead of exact LM centroids: every reader (decode kernel, prefix dequant, any future one) keeps the plain uniform contract — the exact-centroid dequant path is the one with the documented production decode instability, and it stays off. Cost: +1.2% distortion vs exact LM (analytic), +0.8% on real post-FWHT Llama K/V. The legacy 1.16 encoding was +26%. Derivation + Monte-Carlo + real-data table: /vault/amir/efficient-llm/teamily-project/pipelines/oscar_e2e/turbo_lm_check.py.

4Tensor parallelism — multi-GPU and multi-node

Defect 1 — codebook head sharding (ours). Under TP the pool receives the per-rank KV head count while the bundle holds all global heads; boot died on a shape assert (and without it, ranks would have quantized against wrong-head codebooks). Fix: load_vq_codebook takes head_start and slices forward/inverse/mean/codebooks to the rank's contiguous slice; the pool computes the offset from get_tensor_model_parallel_rank() × head_num; TP size must divide the KV head count (no replication support — guarded). Applies to both the K-tier and VQ-V bundles.

Defect 2 — custom all-reduce (stack-wide, hits bf16 too): FIXED, root-caused. TP>1 CUDA-graph capture died in custom all-reduce (get_graph_buffer_ipc_meta → invalid argument). Root cause (confirmed by test + upstream vllm#42609): PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True — set in our serve wrapper for 40GB-card fragmentation — allocates from cuMemAddressReserve VA ranges that cudaIpcGetMemHandle cannot export. The sgl_kernel wheel was innocent. Fix (repo-side serve_oscar.sh): drop expandable_segments when TP>1 (per-GPU pressure is halved there) and keep custom all-reduce; escape hatches DISABLE_CUSTOM_AR=1 and FORCE_EXPANDABLE=1. Measured A/B at TP=2, bs=1 decode: custom AR 132.0 tok/s vs NCCL 122.5 (+7.8%). If your serve wrapper sets expandable_segments, carry the same conditional.

Validation ALL PASS:

  • Loader gate: rank slices are bit-exact slices of the full load; non-divisible sharding raises.
  • TP=2 boots for bf16 / int2 / vq2, per-rank log lines heads=[0,4)/8 and [4,8)/8, needle retrieval correct in all three.
  • Quality parity: stratified 48-row NIAH-8K slice, vq2 TP=2 = 43/48, identical to TP=1, 4 balanced borderline flips; bf16 control flips 1/48 — generic TP reduction-order numerics, not sharding.

Multi-node inference

The rank-sharding fix is exactly what multi-node serving needs: sglang scales past one node by spreading TP ranks across machines (--nnodes / --node-rank / --dist-init-addr), and each rank now loads only its own contiguous codebook slice — node placement is irrelevant to the loader, so the vq2/VQ-V tiers work under any TP layout, single- or multi-node. Two things to know: (a) inter-node all-reduce goes over NCCL automatically (custom AR is intra-node IPC by construction; sglang picks the communicator per link, no flag needed); (b) the KV pools, arenas, and rotations were already per-rank-local, so the codebook loader was the only globally-indexed piece. Status: validated at TP=2 single-node (full battery below); a cross-node topology hasn't been smoke-tested yet — before any multi-node run, do the boot + needle check with the model sharded across machines, and expect models whose KV-head count the total TP size doesn't divide to be rejected by the loader guard (8 KV heads → TP ∈ {2,4,8}).

Usage (single node): TP=2 bash /vault/amir/efficient-llm/teamily-project/pipelines/oscar_e2e/serve_oscar.sh ... --gpu 1,2. Practical payoff: 128K-context serving — a 131K-token bf16 KV cache (~34 GB) cannot fit one A100-40GB, so the RULER-128K cells run TP=2. (First user: the gpqacc128k position-coverage ablation currently in flight — 128K-calibrated K codebook vs gpqacc64k, including a RULER-131072 cell; row set + generator snapshot at /vault/amir/efficient-llm/teamily-project/third_party/samuel_vq/gen_niah.py → /vault/amir/efficient-llm/teamily-project/artifacts/niah_bench/131072/, Llama-tokenizer-budgeted to stay inside native RoPE.)
