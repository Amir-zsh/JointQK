Step 0 · The problem

Why the KV cache, and why keys are special

When a transformer generates text, every new token attends over all previous tokens. To avoid recomputing the past, the model caches two vectors per token per layer per head: a key k and a value v. At long context this cache dominates GPU memory — for an 8-billion-parameter model at 128k context it reaches tens of gigabytes — and every generated token must read a large fraction of it. Shrinking the cache buys longer contexts, bigger batches, and faster decoding at once.

Intuition. Keys and values fail differently. A value error just blends into a weighted average. A key error changes which tokens get attended to at all, because keys sit inside the softmax. That is why this method is built around keys, and why every design choice below asks one question: how does this error propagate into attention scores?

Setup · attention in one line

For a decode query q (dimension d = 128 per head) and cached keys k1 … kT, attention weights are

as = softmaxs ( q · ks / √d ),   output = Σs as vs (1)

Compressing a key replaces ks by a reconstruction k̂s. The damage that matters is not k−k̂2 — it is the logit error q·(k−k̂)/√d, for the queries the model will actually ask.

Step 1 · Calibrate offline · once per model ~30 min GPU, ~26 prompts, 200k tokens

Learn where queries point

Before compressing anything, run the model on a small calibration corpus and record, for every (layer, head) pair, the queries and keys it produces. From these we keep only three summary statistics per (layer, head) — nothing about the calibration texts themselves survives.

Intuition. Queries are not arbitrary vectors: each head asks questions from a narrow, stable cone of directions. If we know that cone, we know which components of a key the model will ever "read" — and which components can be stored coarsely because no query will ever look at them.

Definitions · the three calibration statistics

With N calibration queries qi per (layer, head) — pooled across the head's query group under grouped-query attention — we estimate the mean query, the query second moment, and the key mean:

μ̄q = 1N Σi qi,   ΣQ = 1N Σi qi qi⊤,   μk = 1N Σi ki (2)

ΣQ is a d×d matrix whose eigenvectors are the directions queries actually use, weighted by how much energy they carry. It is the single most important object in the whole method: for any direction u, u⊤ΣQu is the average squared query magnitude along u.

robustness: 8k tokens of calibration suffice; corpus choice moves results little independently validated: OSCAR (2026) proves ΣQ is the optimal rotation target
Step 2 · The basis offline · once per model eigendecomposition, seconds; one d×d matrix pair per (layer, head)

Rotate keys so plain squared error is attention error

Scalar quantizers measure error coordinate by coordinate — implicitly, plain Euclidean error. But step 0 said the error that matters is query-weighted. The fix is a change of basis chosen so those two become the same number.

Intuition. Imagine stretching space so that directions queries care about become long (errors there look big) and ignored directions shrink (errors there look small). After that stretch, a dumb quantizer minimizing ordinary squared error is automatically minimizing attention damage. The transform bakes the "what matters" knowledge into the geometry, so everything downstream can stay simple.

Construction · the whitened query-PCA pair (F, G)

The logit distortion a key error causes, averaged over calibration queries, is a quadratic form in ΣQ:

𝔼q  |q·(k−k̂)|2 = (k−k̂)⊤ ΣQ (k−k̂) (3)

Choose an invertible forward map F (encode) and its inverse G = F−1 (decode), built from the eigendecomposition of ΣQ and scaled so the decode map whitens the query moment:

r = (k − μk) F,   k̂ = r̂ G + μk,   with   G ΣQ G⊤ = I (4)

Substituting (4) into (3) gives the identity the whole codec rests on:

r − r̂2 = (k−k̂)⊤ΣQ(k−k̂) (5)

Plain squared error in code space (left) equals expected attention-logit distortion (right). Every quantizer, allocator, and rate–distortion decision below can therefore work with ordinary squared error and still be optimizing the right thing.

why not plain PCA on keys? attention-aware target beats the raw K⊤K target 70.0 vs 31.1 (OSCAR ablation) — same premise, independent proof a learned transform was trained as a control (248 heads, no overfit) — it made things worse: the basis was never the bottleneck
Step 3 · Importance online · per token at prefill one dot product per key; zero bits transmitted

Predict which tokens attention will read

Within any 64-token window, attention mass is extremely uneven — the top 8 tokens typically carry ~43% of it. Equal bits per token wastes budget on tokens nobody will look at. So each token gets an importance weight computed from its key alone.

Intuition — with a twist. The obvious signal ("how big is this key in query-space?", k⊤ΣQk) turns out to point the wrong way: rank correlation −0.78 with real attention. High-energy keys are logit repellers — tokens the model pushes deep into negative scores, where softmax gradients vanish and quantization error is nearly free. What works is the humble mean-logit signal: does this key score high against the average query? That predicts attended tokens at +0.73…+0.82 and transfers across tasks.

Definition · the ω weight

Per token t, compute the calibrated mean logit and pass it through a clamped exponential centred on the current context's median:

mt = μ̄q⊤ kt√d,   ωt = exp ( τ · clip(mt − mediant mt,  ±c·ln2) ) (6)

with temperature τ = 0.5 and clamp c = 4 bits, both frozen on held-out calibration rows before any benchmark was run. ωt multiplies the token's distortion in step 4 — it steers the allocator and costs zero bits, because the decoder only ever sees the resulting precision choices, never ω itself.

Regime law (measured, three quantizer families): ω is worth +3…+4 F1 when the precision ladder is coarse (the allocator would otherwise starve attended tokens), neutral when the ladder is fine, and mildly harmful on out-of-distribution code — apply it when the rate is tight, skip it when it isn't.

unweighted allocation actively hurts attended tokens (they look expensive) — ω is the correction, not a bonus same signal drives page selection for offloaded tiers: +2.5 F1 SIG over structure-matched controls
Step 4 · Pages + allocation online · per prompt at prefill closed-form per page; <0.1% of prefill compute

Fixed-byte pages, unequal tokens inside

Keys are grouped into pages of 64 consecutive tokens — the block size paged attention servers already use — and every page compresses to the same byte size, so a serving allocator can treat pages as fixed-size blocks. Inside the page, tokens receive different precision: each token picks a "rung" from a small ladder (evict · coarse · … · fine), and a 2–3-bit rung label per token tells the decoder what was chosen.

Intuition. A page is a knapsack. Each token wants bits; the page has a fixed budget; ω says whose distortion hurts most. The optimizer finds the single "exchange rate" λ between bits and damage at which the page budget exactly clears — expensive-but-unimportant tokens drop to coarse rungs, attended tokens climb to fine ones. Per-token choice is also what makes fixed pages fillable: uniform precision strands ~18% of the byte budget; per-token allocation fills 99.6%.

Formulation · per-page Lagrangian rate–distortion

Token t at rung j costs Rj bits and incurs code-space distortion Dt(j) = rt − r̂t(j)2 (computed against the actual reconstruction — quantize, decode, measure). The page solves

minj1…j64 Σt ωt Dt(jt)   s.t.   Σt Rjt ≤ Bpage (7)

Relax with a multiplier λ ≥ 0; the coupled problem splits into 64 independent one-liners,

jt(λ) = arg minj [ ωt Dt(j) + λ Rj ] (8)

and λ is found by bisection (about 40 halvings in float64) until the budget constraint in (7) is met exactly. The budget Bpage already has the side information subtracted: page header, the per-token rung labels, and per-token norms where the family uses them — every bit the decoder needs is charged, nothing rides for free.

Step 5 · Sinks online · positions 0–3 of every sequence forced max precision; position-derivable, zero extra labels

The four tokens you must never damage

The first few tokens of a sequence — the attention sinks — absorb 19–84% of attention mass per head. They are also statistical outliers: their norms sit 2.7–5.4× beyond the 99.9th percentile of ordinary keys, and their directions are outliers too. Every quantizer tuned on "typical" keys destroys them, and every accuracy proxy fails to notice until generation collapses into whitespace.

Intuition. Sinks are the softmax's pressure valve: the model parks probability mass there when it wants to attend to nothing. Corrupt a sink and that parked mass floods everywhere else — a global failure caused by four tokens. Since their positions are always 0–3, protecting them needs no signalling at all: both encoder and decoder simply know.

Rules · three hard-won invariants

(i) Force the top rung for positions 0–3 and debit their cost from page 0's budget before the optimizer runs. (ii) Every quantization grid must contain an exact zero level — grids without one inflate every key's norm coherently, and softmax amplifies coherent bias (F1 → ~0 while per-token metrics look fine). (iii) Scale handling must be absolute, not data-fit for sinks: e.g. an absolute mid-tread grid on unit directions,

ûc = round(127 uc)127,   c = 1…d (9)

which is outlier-proof because unit-vector coordinates are already bounded in [−1, 1] — no fitted scale exists for an outlier to break.

failure physics measured: q999-fitted scales clipped sinks → sink mass 0.84 → 0.007 → whitespace generation independently confirmed: OSCAR's BF16 sink window is a requirement — removing it in our emulation corrupts sinks on Llama
Step 6 · Entropy coding online · encode once at prefill encode <0.1% of prefill; decode only on tier loads

Where the last 4 F1 points live

Within each rung, coordinates are quantized by a deadzone scalar quantizer and the resulting symbol stream is compressed with a range coder (rANS) whose probability tables are frozen from calibration. This is the one component that cannot be replaced by anything cheaper — we know, because we tried the entire alternative class and measured the gap.

Intuition. After the whitening of step 2, most coordinates of most tokens are tiny — nearly zero. An entropy coder charges what a symbol is worth: "zero, again" costs a fraction of a bit, while rare large values pay full price. Fixed-width codes must pay the same bits for every coordinate regardless. That density-adaptation is worth 4+ F1 points at 1.5 bits/coord, and no fixed-width mechanism we built — trellis codes, E8 lattices, sparse top-K coding, learned bases — recovers it.

Definitions · deadzone quantizer + achieved rate

With step size Δ and a widened zero bin (deadzone), encode and decode are

sc = sign(rc) ·  max(0,  ⌊ |rc|/Δ − θ + 1 ⌋),   r̂c = sign(sc) (|sc| + θ − ½) Δ (10)

The coder stores symbol s in −log2 p(s) bits against the frozen calibration model p, so the page's payload approaches the empirical entropy H(s). All rates reported anywhere in this project are held-out and all-in: probability tables frozen on calibration data, evaluated on unseen prompts, with headers, rung labels, and coder state all charged.

the no-EC frontier is mapped and closed: best random-access codec 42.6 vs EC 46.8 at 1.5 b/c; 5× training data moved it 0.6 — the gap is the entropy model itself
Step 7 · Serving decode path · zero added cost

Mode A: compress once, decode never

The final piece is where compression sits in the serving stack — and the answer is what makes the whole design deployable despite entropy coding being serial and slow to decode.

Intuition. A resident compressed cache must re-decode the entire context for every generated token: at 64k context that is ~2 billion symbols per token — measured at ~1.8 seconds against a ~5 ms attention budget. Hopeless, and unfixable, because entropy streams cannot be random-accessed mid-page. So don't decode at decode time: compress at prefill, immediately reconstruct, and let the cache hold the reconstructions. Generation touches ordinary fp16 tensors; the quality effect of compression is fully present (the keys are the quantized ones); the cost of decompression is zero.

Straight talk · where memory is and is NOT saved

Mode A does not shrink the hot GPU cache. The resident tensors are ordinary fp16 — the reconstruction k̂ occupies exactly as many bytes as k did. What Mode A buys on the hot tier is quality isolation (F1 measures pure codec damage) and zero decode cost. The memory wins live elsewhere:

The study's contribution is that this table is now measured, so the choice is an engineering decision, not a bet.
