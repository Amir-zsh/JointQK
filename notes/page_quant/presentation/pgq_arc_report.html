1 · Background & problem definition

1.1 · What the KV cache is and why it is the bottleneck

A transformer generates text one token at a time. To produce token t+1, every attention layer compares the current query vector q against the key vector ki of every previous token i, turns the comparison scores into weights with a softmax, and averages the previous tokens' value vectors vi with those weights:

zi=q·kid,ai=ezi∑jezj,output=∑iaivi.

To avoid recomputing them, every past token's ki and vi are kept in GPU memory — the KV cache. It is big: for Qwen3-8B (36 layers, 8 KV heads, head dimension d=128), each token costs 2×36×8×128 numbers ≈ 144 KiB in fp16 — about 18 GB at a 128k-token context. Worse, generating each single token requires reading the entire cache once. Long-context decoding is therefore memory-bandwidth-bound: the GPU spends its time moving cache bytes, not doing arithmetic. Compressing the cache buys capacity (longer contexts, larger batches) and speed (fewer bytes per step) simultaneously.

1.2 · What compression must preserve

We compress keys by storing a compact code and reconstructing an approximation k^i when needed. The right question is not "is k^i close to ki?" but "are the attention scores that future queries compute preserved?" — because the scores are all the model ever sees of the keys. The error that matters is the logit error q·ki−q·k^i=q·(ki−k^i), and it must be small for the queries this layer and head actually produce, not for arbitrary vectors. Section 3 turns this into a precise, measurable objective. (Values are compressed too, but in all experiments here the V-side is pinned to a standard 2-bit baseline so that K-side comparisons are clean.)

1.3 · Serving constraints

Production inference stacks (vLLM, SGLang) store the cache in fixed-size pages — blocks of 64 tokens here — managed by a memory allocator like OS memory pages. This imposes three hard constraints that shaped every design choice below:

  • Fixed bytes per page. The allocator needs every page to occupy a predictable number of bytes. Variable-length coding across pages breaks paged memory management.
  • Random access. Any page must be decodable on its own, at any time, without touching other pages, because attention reads all pages every step.
  • Kernel-implementable decode. Whatever the decoder does per token must map to cheap GPU primitives — integer unpack, small table lookup, dot product — because it runs inside the innermost attention loop. (Our Python research code stores dequantized fp16 for convenience; the format is designed so a real kernel never has to.)

1.4 · The thesis: bits should vary across tokens

Two families of prior work bracket the design space. Uniform quantization (NVIDIA's OSCAR, KIVI, TurboQuant) gives every token the same low precision, e.g. INT2. Eviction (SnapKV, H2O, Expected Attention) keeps some tokens at full precision and deletes the rest — implicitly, 16 bits or 0 bits. Both are extreme points of one decision: how many bits does each token get? Eviction's success proves that many tokens carry little attention-relevant information; uniform quantization's success proves most tokens survive coarse coding. A page codec that can give different tokens different widths — down to zero — contains both as special cases, so with a competent allocator it should never lose to either at matched total bits. That is the central bet of this project, and pgq6 (Section 8) extends it one axis further: the page may also store fewer rows than tokens.

All-in accounting. A page at budget b may use at most B=b·d·n bits including everything: payload, the 96-bit page header, every 3-bit rung id, and the full cost of any escape or forced-precision token. Reported rates are measured from encoder telemetry, not nominal settings (e.g. the shipping config is nominally 2.0 and honestly 2.13 b/c once the recency window is charged). This convention makes comparisons against other methods fair — many published rates quietly exclude metadata, which at INT2 scales is not small.

2 · The pipeline at a glance

Five stages. Everything expensive happens offline (once per model) or at encode time (once per sealed page); the decode path — the part that runs for every generated token against every cached token — is deliberately the cheapest thing in the system.

1

Calibrate — learn what queries look like (offline, once per model)

Run a few hundred long prompts through the model. For every (layer, KV-head), record second-moment statistics of the queries and keys the model actually produces. Intuition: quantization error only matters in directions future queries will probe; the statistics are the map of those directions. (§3)

2

Rotate — change coordinates so error budgeting becomes easy (offline)

Build a linear transform per (layer, KV-head) with two properties: squared error in the new coordinates equals attention-weighted error exactly (no matrix in the loop ever again), and signal energy concentrates in the first coordinates so the tail can be coded cheaply or not at all. (§4)

3

Allocate — spend each page's bit budget where it hurts least (encode time)

Each token gets one of ≤ 8 precomputed width patterns ("rungs"). A per-page rate–distortion optimizer picks every token's rung so total distortion is minimized subject to the page's fixed byte budget. Hard-to-code, high-impact tokens ride high rungs; redundant tokens sink toward zero. (§5 — explained in full)

4

Quantize — snap coordinates to grids, with two positional safety rails

Coordinates snap to Gaussian-optimal (Lloyd-Max) levels scaled by calibration. Two protections triggered by position alone: the first 4 tokens (attention sinks) escape to a generous 8-bit grid, and the last 4 pages of the prompt are pinned to the top rung (the recency window). (§6)

5

Serve — fold all constants into the query; decode on integer codes

At decode time the basis, scales, and mean collapse into one transform of the query per step. The stored page is integer codes plus a 3-bit rung id per token — no per-token scales or zero-points, which are OSCAR's main per-token overhead. (§7)

3 · Calibration: measuring what matters

Intuition. Plain mean-squared error on keys is the wrong target. A large reconstruction error along a direction that no query ever points at costs nothing; a small error along a direction queries constantly probe corrupts every future attention score. So before compressing anything we measure, per (layer, KV-head), where queries point — and we weight all reconstruction error by that.

Concretely, we run a calibration corpus (≈ 400 long prompts; 12 sufficed for the Qwen refit) through the model once and pool, per (layer, KV-head):

ΣQ=𝔼[q⊤q],ΣK=𝔼[k⊤k],μ=𝔼[k],μq=𝔼[q],

with queries taken exactly as the attention kernel sees them (after rotary position encoding), and — because these models use grouped-query attention — all query heads in a KV-head's group pooled together. The second moments are uncentered: attention uses raw q·k, so the statistics must too.

Why ΣQ is exactly the right weight. For a key reconstruction error e=k−k^ (a row vector), the squared logit error averaged over the query distribution is:

𝔼q[(q·e)2]=𝔼q[eq⊤qe⊤]=eΣQe⊤.

No approximation — this is an identity. The quantity eΣQe⊤, which we call the Q-weighted error or logit error when aggregated, is the single objective every component below optimizes and the screening metric every design decision was judged on. Screening always ran on held-out rows, scoring reconstructions against each row's own real queries (not the calibration queries), and — a process rule enforced throughout the arc — every format choice was frozen against this proxy before any downstream benchmark score was looked at.

4 · The query-aware basis (qpca_unc)

Intuition. We want a coordinate system where two things are true at once: (a) one unit of quantization noise costs one unit of logit error in every coordinate — then a simple scalar quantizer per coordinate is the right tool and the allocator can compare coordinates directly; and (b) the signal's energy is concentrated in the first few coordinates — then the tail coordinates can be coded with 2 bits, or zero. The construction below (query-weighted PCA, "QPCA") achieves (a) exactly and (b) empirically very strongly.

Construction (per layer and KV-head, offline). Eigendecompose the query moment and form a whitener:

ΣQ=UΛU⊤,W=Λ1/2U⊤⇒ΣQ=W⊤W.

Push the key energy through the whitener and diagonalize it:

M=WΣKW⊤=VDV⊤,F=W⊤V  (forward),G=F−1  (inverse).

Keys are encoded as r=(k−μ)F and reconstructed as k^=r^G+μ. Two properties do all the work:

  • Isometry. Let ε=r−r^ be the error in code space, so the key error is e=εG. Then
    eΣQe⊤=εGW⊤WG⊤ε⊤=εV⊤W−⊤W⊤WW−1Vε⊤=‖ε‖2,
    using G=(W⊤V)−1=V⊤W−⊤ and V⊤V=I. Plain squared error in code space equals query-weighted error in key space, exactly. Every distortion the allocator computes from here on is a simple sum of squares — no matrices, no weights — yet it is always the attention-relevant quantity.
  • Energy compaction. The diagonal of D sorts coordinates by query-weighted key energy. Measured spectra are heavily front-loaded: most energy sits in a small fraction of the 128 coordinates. This is what makes "give the tail 0 bits" a good trade rather than an act of vandalism.

How much does the basis matter? A controlled ablation (pgq4 screening) swapped only the rotation under an otherwise identical quantizer and allocator: OSCAR's per-layer rotation gives 5.9× higher logit error, and a symmetric whitening variant (r_sym) gives 7.4× higher. The basis is the single largest quality factor in the entire system — larger than any allocator or grid decision. (The _unc suffix marks a subtle lesson: an earlier variant centered some statistics and not others, and the resulting calibration asymmetry masqueraded for a while as a real quality gap between methods.)

5 · The rate–distortion optimizer, exactly

This is the heart of the codec, so it gets the full treatment. There are two allocation problems, solved at different times:

  1. Offline: design a small menu of per-coordinate width patterns ("profiles" / "rungs") — the options tokens will choose from (§5.1).
  2. Encode time, per page: assign one rung to each of the 64 tokens so the page exactly fits its byte budget with minimal total distortion (§5.2). This assignment problem is "the RDO".

5.1 · Offline: building the width profiles

Intuition. After the rotation, coordinate importance falls off steeply — so bit-width should fall off along the coordinate axis too. But letting every token choose an arbitrary 128-vector of widths would need enormous metadata. The compromise: precompute at most 8 good width patterns and let each token pick one with a 3-bit id.

Mechanics. The 128 coordinates are grouped into 4 blocks of 32 (widths change only at block boundaries — this is a kernel constraint: fixed strides and byte alignment per block). Allowed widths are w∈{0,2,3,4,6} bits per coordinate. A profile is a monotone non-increasing width 4-tuple, e.g. (4,3,2,0) = 4 bits for coordinates 1–32, 3 bits for 33–64, 2 bits for 65–96, nothing for the tail. Its rate is exact: R=32(w1+w2+w3+w4) bits per token.

For each rate target in a fixed ladder, the profile is chosen by measured water-filling on the calibration fit pool: quantize the pool's codes at every (block, width) combination, record the actual per-block distortion D^b(w) — including clipping and grid snap, not a Gaussian formula — and keep

profile(T)=argmint monotonecost(t)≤T ∑b=14D^b(tb).

"Water-filling" is the shape this produces: bits flow to the blocks where the next bit buys the most distortion reduction, until marginal value equalizes across blocks. (An earlier version used the textbook 4−w Gaussian decay model instead of measured D^b; replacing it with measurement was worth a meaningful chunk of the final margin.) One more freeze-time decision: whether all KV-heads in a layer can share one profile ladder. The rule (frozen in advance) was "share if the pooled penalty is under 3%" — on Llama sharing costs 1.9% (shared per layer), on Qwen 6.2% (kept per head). Same rule, different outcome; the format supports both.

5.2 · Encode time: the per-page RDO

The problem, precisely. A page holds n=64 tokens. For each token t and each rung ρ, the encoder computes — by actually quantizing, so overload and grid snap are priced in — the code-space distortion

Dt,ρ=‖rt−r^t(ρ)‖2,

which by the §4 isometry is the expected squared logit damage to token t. Each rung has exact rate Rρ (its profile bits). The page must fit its all-in budget, so the free payload is B=bdn minus side bits (96-bit header + 3 bits × 64 rung ids) minus forced costs (sink escape, recency window — §6). The optimization problem is:

minρ(1),…,ρ(n) ∑t=1nDt,ρ(t)s.t.∑t=1nRρ(t)≤B.

This is a (multiple-choice knapsack) combinatorial problem — 864 assignments — but it has a classical, essentially exact solution.

Step 1: Lagrangian relaxation decouples the tokens. Introduce a price λ≥0 per bit and move the constraint into the objective:

L(λ)=∑t[Dt,ρ(t)+λRρ(t)].

The sum is separable — each token minimizes its own term independently:

ρλ(t)=argminρ (Dt,ρ+λRρ).

Read λ as the exchange rate between bits and distortion: a rung one step higher is worth taking only if the distortion it removes exceeds λ times the extra bits it costs. At λ=0 bits are free and every token takes the top rung; as λ→∞ every token drops to the cheapest rung. Crucially, total spent rate ∑tRρλ(t) is non-increasing in λ — which turns "find the right λ" into a one-dimensional search.

Step 2: bisection finds the page's price.

for each page:                                  # all pages solved in parallel, fp64
  lo, hi = 0, λ_max                             # invariant: rate(lo) > B ≥ rate(hi)
  repeat 40 times:
    mid = (lo + hi) / 2
    ρ(t) = argmin over rungs of  D[t,ρ] + mid · R[ρ]     # ties → lowest index
    if Σ_t R[ρ(t)] > B:  lo = mid               # too expensive → raise the price
    else:                hi = mid               # fits → try a lower price
  final assignment at λ = hi                    # guaranteed within budget

Taking the final assignment at the feasible end (hi) guarantees the page never overflows; ties broken by lowest index make the result exactly reproducible across CPU and GPU. (A page that cannot fit even with every token at minimum rate is flagged in telemetry; measured overflow across all studies: 0.)

Step 3: greedy refinement spends the leftovers. The Lagrangian solution only ever lands on each token's lower convex hull of (rate, distortion) points, and bisection stops just under the budget — typically leaving a few dozen spare bits. A cleanup pass runs up to 8 rounds; in each round, each page upgrades the single token with the best ratio

ΔDΔR=Dt,ρ(t)−Dt,ρ′Rρ′−Rρ(t)

among upgrades that still fit. This closes the integrality gap in practice: realized rates in the held-out gates are exact to four decimals (e.g. 2.0000, 1.4960) with zero overflow.

A worked example

Three tokens, four rungs with rates R=(0,64,160,288) bits. Token A is high-energy and hard to code (a rare token the head cares about), token B is typical, token C sits in a redundant run. The measured distortions:

tokenD @ rung 0 (0 b)D @ rung 1 (64 b)D @ rung 2 (160 b)D @ rung 3 (288 b)
A (hard, important)9002406012
B (typical)40090256
C (redundant)4082.50.8

At a cheap bit price λ=0.1, the per-token costs D+λR are minimized at rung 3 for A (cost 40.8), rung 3 for B (34.8), but only rung 1 for C (14.4 — its distortion is already tiny, more bits aren't worth it): total 640 bits. Raise the price to λ=0.5 and A drops to rung 2 (140), B to rung 2 (105), and C all the way to rung 0 (40 — evicted to the mean): total 320 bits. If the page budget were 400 bits, bisection would settle between these prices, and refinement would then push C back up to rung 1 with the 84 leftover bits. Notice the emergent behavior — C is sacrificed first, A holds its bits longest — no heuristic ranks tokens; the price mechanism does it.

What rung 0 means — and its limits

Rung 0 (all widths zero) reconstructs the token at the calibration mean: r^=0⇒k^=μ. The token still exists — it occupies a softmax slot and costs its 3-bit id — but carries no token-specific information. This is soft eviction, discovered by the optimizer whenever a token's information isn't worth its bits. It is also the point where width allocation hits a wall: at very tight budgets the allocator is forced to zero out many tokens, and "reconstruct at the corpus mean" is a brutal approximation for all of them at once. Section 8's merging exists precisely to give the optimizer a better option in that regime.

5.3 · Optional importance weighting (and why it ships disabled)

The distortion can be weighted per token, Dt,ρ→ωtDt,ρ, making the allocator protect tokens with high predicted attention. The format constraint is that ωt must be computable from information available at decode time too (the "phase-symmetric" signal policy — see §9.7): the shipping ω uses only the calibration mean query direction, ωt=exp(τ(μq·kt/d−median)), clamped to ±4 bits of effect. Measured at F1, ω is a wash on these benchmarks (+0.81 [−0.51, +2.12] pooled), so the shipping config runs with τ=0 — the un-weighted RDO. It matters here mostly as evidence: even a cheating importance signal fails to beat the plain optimizer (§9.7).

6 · Quantizers, sinks, and the recency window

6.1 · Lloyd-Max grids

Intuition. Once a coordinate has a width, say 3 bits, we must place its 23 representable levels. Uniformly spaced levels are wrong for bell-shaped data: they waste levels in the rare tails and starve the dense center. The Lloyd-Max construction places levels to minimize expected squared error for a known distribution — each level sits at the centroid of the data that snaps to it.

Rotated coordinates are near-Gaussian with calibrated per-coordinate scale σj, so each width w uses precomputed unit-Gaussian Lloyd-Max levels cw[·], shared everywhere and scaled at decode by σj:

r^j=σj·cw[nearest(rj/σj)],

with the near-zero level forced to exactly 0 (so dead coordinates and rung-0 blocks reconstruct exactly, and integer code 0 means "nothing"). Two exceptions: the top width stays a covering uniform grid — its job is bounding worst-case error for escape duty, not minimizing average error — and early experiments that used uniform grids at 2–3 bits clipped the bulk of the distribution badly enough to cost double-digit F1, which is why the LM grids exist.

6.2 · The sink escape

The first few tokens of a sequence become attention sinks: keys with enormous norms that every later token attends to, functioning as the softmax's resting place. Their coordinates run 3–5× beyond the 99.9th percentile of the calibrated grids, so any narrow grid clips them hard — and because sinks appear in every softmax denominator, corrupting them poisons all attention scores at once (an early, expensive lesson: F1 collapse traced to exactly this). The fix is positional: tokens at positions 0–3 bypass the rungs entirely and encode on an absolute 8-bit per-coordinate grid sized to cover calibration sinks with margin. Position is known to the decoder, so this costs zero metadata; page 0 simply pays the extra bits from its budget. The assumption "sinks live at positions 0–3" was re-verified on Qwen before freezing: median 11.7% of attention mass at those positions, and no displaced structural sink found in 160 probes.

6.3 · The recency window

pgq4's cleanest discovery. On code completion (lcc) — the most out-of-distribution task relative to the calibration corpus — codecs with per-token adaptivity beat static ones by ~10 F1. Hypothesis (registered before the confirming run): code queries attend overwhelmingly to the immediately preceding context, so the gap is about recent tokens specifically, not about adaptivity in general. Test: force the last 4 pages of the prompt (256 tokens) to the top rung. Result: the entire gap closes (lcc 40.2 → 50.1 on Llama; reproduced +7.0 on Qwen), nothing else moves, cost +0.13 b/c, and the trigger is again pure position — zero metadata. This "rw" window is part of the shipping config and, like the sink rule, ports to the kernel as a trivial position check routing tokens to a full-precision tier.

7 · Serving: the fold identity

Intuition. A naive decoder would reconstruct every cached key — multiply by G, scale, add μ — every step. But all of those are calibration constants, identical for every token in a head. So instead of undoing the transform once per cached token, apply it once per step to the one new query, and let the kernel dot the transformed query directly against raw integer codes.

The stored reconstruction is k^=(s⊙c^)G+μ, where c^ are the integer LUT codes, s the static per-coordinate scales (σj times grid constants), and ⊙ elementwise product. Then for any query q:

q·k^=q((s⊙c^)G)⊤+q·μ=(qG⊤)·(s⊙c^)+q·μ=((qG⊤)⊙s)⏟q~ (once per step)·c^+q·μ⏟cancels.

The q·μ term is the same for every cached token in the head, and softmax is invariant to adding a constant to all logits — it cancels exactly. So the entire decode-side cost of the transform is one d×d multiply of the query per (layer, head-group) per step, and the inner loop computes q~·c^ — a dot product against integer codes. What the kernel reads per token: packed codes (2–6 bits per coordinate as the rung dictates) and a 3-bit rung id. Nothing else. Contrast OSCAR INT2, which stores an fp16 scale and zero-point per token-group — 32 bits of metadata fetched inside the attention loop — because its grids are fit per token at encode time rather than folded from calibration. At the shipping 2.13 b/c the K-side read is ~34 bytes/token vs 256 bytes in bf16 (≈ 7.5×) and vs ~36 bytes for OSCAR INT2 (payload + metadata). Since long-context decode is bandwidth-bound, byte ratios of this kind are the entire speed story — §9.4 covers what is measured vs pending on that front.

8 · Token merging (pgq6), exactly

8.1 · The idea and the question it answers

Intuition. Width profiles vary bits per coordinate; the RDO varies bits per token; the remaining axis is the number of stored rows itself. Long contexts are full of locally redundant runs — code punctuation, boilerplate, repeated structure — whose keys are nearly identical. If a 64-token page stores only m<64 representative rows, every surviving row gets more bits under the same page budget, and attention reads fewer rows. This makes eviction (rows at zero information) and OSCAR (all rows, uniform bits) two corners of a single design space, and directly answers the project's founding question: can n tokens go in and m < n rows come out, at the same quality?

8.2 · The mechanism, step by step

Where it runs. In code space r, because of the §4 isometry: unweighted Euclidean clustering there is query-weighted clustering on raw keys — no weighting needed anywhere in the algorithm.

What may merge. Only contiguous runs of adjacent tokens within one page. This is a deliberate format restriction: the cluster map of a contiguous partition is just the list of run lengths — a 6-bit count per stored row — whereas arbitrary clusters would need per-token pointers (≈ 6 bits per token, erasing the savings).

How runs are chosen. Bottom-up greedy (Ward) merging. Start with 64 runs of one token each. Merging two adjacent runs a,b (sizes ca,cb, centroids r¯a,r¯b) increases the total within-run squared error by exactly

Δab=cacbca+cb‖r¯a−r¯b‖2,

so the algorithm repeatedly merges the adjacent pair with the smallest Δ — always the cheapest information loss first. Each merge reduces the row count by one, producing a nested hierarchy of partitions.

Do pages merge into an arbitrary number of rows, or is the target fixed?

Fixed. The hierarchy is snapshotted at exactly three row counts — m∈{64,32,16}: unmerged, 2× merged, 4× merged. Which tokens share a row is data-dependent (whatever runs the Ward pass formed by then), but a page's row count is always one of these three values. The reason is the serving constraint from §1.3: fixed levels mean pages come in a small set of byte-size classes {S,S/2,S/4}, which a paged allocator can handle; arbitrary m would reintroduce variable-size pages through the back door. Each page then makes a 2-bit choice of level: the per-row width RDO of §5.2 is run at each level under the same byte budget B, and the page keeps whichever level achieved the lowest total distortion (ties broken toward less merging). Empirical footnote: the 16-row level was never chosen by the optimizer at any tested rate (1.25–2.0 b/c), so deployment needs only two page size classes.

How merged rows enter the RDO. Merging composes cleanly with the width allocator because distortion decomposes exactly. For a run C of size c with centroid r¯, reconstructing every member at the quantized centroid Q(r¯) costs

∑i∈C‖ri−Q(r¯)‖2=∑i∈C‖ri−r¯‖2⏟spread (fixed by clustering)+c‖r¯−Q(r¯)‖2⏟c×ordinary quantization error,

the cross term vanishing because errors are measured about the centroid (∑i∈C(ri−r¯)=0). So at any level, each row presents the RDO a distortion "spread + c · grid error" and a rate "profile bits + 6-bit count", and the same λ-bisection of §5.2 allocates widths across rows. A merged run of 4 at a 160-bit profile costs 160+6 bits ≈ 41.5 bits per original token — a rate point below the cheapest non-zero rung (64 bits) that still carries real, local information. Merging fills the gap in the rate ladder between "own row" and "erased".

Protections. Page 0 (sinks) and recency-window pages never merge. Sinks and the recent context are exactly the tokens whose individuality matters most.

8.3 · How is merging different from giving a token zero bits?

They sound similar — both "give up" on tokens — but they differ in what survives, what it costs, and what attention computes. Side by side, for a run of c=4 redundant tokens:

rung 0 (zero bits) × 4merged run of 4
each token reconstructs tothe global calibration mean μ — identical for every zero-bit token in the corpusthe run's local centroid — specific to these 4 tokens
information keptnone (token-specific and local content both gone)everything the 4 tokens share; lost: only their within-run differences
reconstruction erroreach token's full distance to μ (large)within-run spread (small — that's why the run was chosen)

rows read at decode41 (fewer bytes and fewer FLOPs)

Three points deserve emphasis:

  • Different collapse targets. Zero bits collapses a token onto the corpus-wide mean — "forget this token". Merging collapses it onto its neighbors' mean — "this token said the same thing as its neighbors". When local redundancy exists, the second is a strictly gentler approximation, and the Ward pass only forms runs where it is.
  • A different point on the rate axis. Rung 0 is all-or-nothing: 0 payload bits. Merging creates fractional per-token rates (payload ⁄ c) that the width ladder cannot express — with actual content, unlike rung 0.
  • Why it can't just be "one more rung". A rung is a per-token, independent decision — exactly what makes the §5.2 Lagrangian decouple. "Merge with my neighbor" couples adjacent tokens, so it cannot be a column in the same per-token argmin. That is why it enters the optimizer one level up, as the per-page level choice over jointly-clustered snapshots, with the per-row RDO running inside each candidate.

The empirical signature matches the theory: at 2.0 b/c (bits ample) the level choice picks "unmerged" for 100% of pages — merging costs nothing when unneeded — while at 1.0 b/c, where the width-only codec is forced to zero out many tokens and its error explodes (0.01233), merging holds error to 0.00894 (−28%): sharing beats forgetting.

8.4 · Why merged attention is exact (the replication–bias identity)

Merging would be worthless if serving m rows changed the attention semantics. It doesn't — up to the already-counted key approximation, it is an identity. Suppose c cached tokens all had exactly the key k¯, with values v1,…,vc. Their joint contribution to attention is

∑i=1ceq·k¯vi=ceq·k¯v¯=eq·k¯+logcv¯,v¯=1c∑ivi,

in both numerator and denominator of the softmax. So one stored row (k¯, v¯, logc) — centroid key, mean value, and a logit bias of logc — reproduces the c tokens exactly. The bias is one scalar add before the online-softmax max (or, folded as a (d+1)-th coordinate with q~d+1=1, it works in an unmodified FlashAttention kernel). The only approximation in the whole construction is that the original keys were not exactly k¯ — and that error is precisely the "spread" term the RDO already accounted for in §8.2. Our evaluation harness serves the replication form (centroid repeated at each member position), which by this identity is mathematically identical to the deployment form — so measured F1 is deployment F1, verified end-to-end by a direct attention-output check (§11.6).

9 · The page-level transform (pgq8), exactly

9.1 · The idea

Intuition. Everything so far treats each token's key as an independent object to compress. But neighboring tokens are highly redundant — merging (§8) proved it, crudely, by making some neighbors share one row. The sharper move, proposed as a direction change mid-arc: apply a transform at the page level, so the transform output mixes information about every token inside the page — then quantize that. This is what image codecs do when a DCT mixes all pixels of a block: correlated inputs become a few high-energy coefficients plus many near-zero ones, and the allocator (§5, reused unchanged) starves the near-zero ones automatically. Merging becomes the crude special case — keeping only "average" coefficients and discarding the rest — while the transform keeps graded detail at low cost. It is also the first design in the arc that steps outside the class of coders the §11.1 entropy-coding wall actually bounds: that wall is a bound on coding tokens independently.

9.2 · Construction, and why nothing downstream breaks

A page in code space is a matrix R∈ℝ64×d (rows = tokens, already in the §4 basis). Take the orthonormal DCT-II along the token axis:

Y=DR,DD⊤=I,R^=D⊤Y^  (decode),

and feed Y's coefficient rows — instead of token rows — through the existing width-profile rung RDO. Two invariances make this a drop-in:

  • The metric survives. Orthogonality gives ‖Y−Y^‖F2=‖R−R^‖F2, and §4's isometry already equates that with query-weighted logit damage. Every distortion the allocator computes keeps its exact meaning.
  • The fold identity survives. Page logits become
    zpage=R^q~⊤=D⊤(Y^q~⊤),
    one extra 64-point inverse transform per (page, query head) — measured later at ±6% kernel cost, i.e. free.

What does change: grids need per-(coefficient-row, coord) scales σsj (the DC row carries ~8× a token row's scale), fitted from the same calibration pool — the ONLY refit; basis, profiles, ladder, and rate accounting stay frozen. Protected pages stay out entirely: page 0 (sinks), recency-window pages, partial tails, and decode-ring chunks are identity-coded — per-token protections remain per-token, bit-identical to pgq4 there (test-pinned).

9.3 · Why the DCT specifically (measure first, build second)

Before implementing anything, a probe measured the token-axis structure on both models' calibration pools (530k+ pages each; selection rows untouched). Three facts picked the design:

  1. The correlation is large and long-range. Lag-1 correlation of code rows is 0.70 (Llama) / 0.79 (Qwen), decaying to only 0.48/0.63 at lag 16. Slow decay is precisely where a graded transform beats a hard 2:1 merge. (RoPE, the obvious worry, scrambles only ~10–15% of this structure — measured by analytic de-rotation.)
  2. The process is stationary → the DCT is already optimal. The pooled 64×64 token covariance is Toeplitz to cv ≈ 0.015, and the best possible fixed transform (the pooled-covariance KLT) beats the DCT by under 2% in coding gain — the classical "DCT is the KLT of stationary sources" result, verified in the data. So: a hardcoded matrix, no calibration, no sideband.
  3. The gain is worth real bits. Coding gain (the AM/GM ratio of coefficient-row energies; high-rate theory: bits saved per sample = 12log2G) is 2.50/5.96 ⇒ ~0.66/1.29 bits per coordinate. A matched-rate simulation — same allocator, same grids, only the row basis changed — predicted SE ratios of 0.58–0.65, which the real screening then reproduced almost exactly (§11.5).

9.4 · Transform vs merging vs zero bits — one family, three strengths

All three "give up" information; they differ in what survives. Zero bits (§5) collapses a token to the corpus mean — everything lost. Merging (§8) collapses it to its run's mean — within-run differences lost, a hard 0/1 choice, only adjacent near-duplicates qualify. The transform keeps a graded decomposition: smooth long-range structure lands in cheap low-frequency rows, and detail is attenuated coordinate-wise rather than discarded token-wise. The data ranked them exactly that way at 1.0 b/c: proxy error 0.0123 (widths only) → 0.0089 (merging, −28%) → 0.0062 (transform, −50%). Merging keeps one advantage the transform lacks — it reduces the ROW COUNT (fewer dot products, smaller V) — so the two compose in principle (deferred direction).

10 · Making it fast: the fused decode kernel (pgq7)

10.1 · What "fast" requires

Intuition. Long-context decode is a memory-bandwidth race: every generated token must read every cached token once. A compressed cache only helps if the kernel reads the compressed bytes directly — decompressing to fp16 first would spend the very bandwidth being saved. So the deliverable is a fused kernel: unpack + dequantize + attend in one pass, mirroring the architecture of NVIDIA's OSCAR (whose entire INT2 path is plain Triton — proof this needs no custom CUDA). The full per-token read is: packed codes (2–6 bits/coordinate as the rung dictates) plus a 3-bit rung id. Everything else — basis, scales, grids, the DCT matrix — is calibration-static and folds into per-step constants.

10.2 · From bytes to attention output, step by step

1

Pack (once, at page seal)

Each row's codes pack little-endian in 32-coord blocks (width w → 4w bytes, byte-aligned by construction for the ladder {2,3,4,6}). Rows are grouped by rung, so every rung-segment is a dense (rows × constant-stride) byte matrix. Golden-vector tests pin pack → unpack → dequant to BIT-identity against the compressor, for token rows and coefficient rows alike.

2

Fold (once per decode step)

q~=qG⊤ per (layer, head-group) — §7's identity, now per coefficient row: the kernel computes us=(q~⊙σs)·c^s from integer LUT codes c^s, then z=uD per transformed page.

3

Phase A — dequantize, coalesced (one launch per rung)

Because a rung-segment is dense with a compile-time stride, a 64-row tile is one contiguous read; widths and LUT bases are compile-time constants (one compiled kernel variant per rung — OSCAR's per-tier launch pattern, one tier per rung). Bit-extraction, LUT lookup, scale multiply, then a tensor-core dot against the folded-query tile; results scatter into a per-token logit buffer u.

4

Phase B — transform, softmax, values (per page)

Load the page's u tile, apply z=uD where the page is transformed (one 64×64 tensor-core dot), run the online-softmax update, accumulate pV (V in fp16 for now), and emit split-K partials. A reduction merges splits plus the torch-served tier (sinks, partial tail) — the same shift-invariant softmax merge used everywhere in this document.

5

Capture the whole step in one CUDA graph

Phase A is ~7 small launches; at short contexts, launch overhead dominated. One CUDA graph replays the entire step — standard decode-serving practice (SGLang runs decode under graphs), and every baseline in the benchmark gets the same treatment.

10.3 · The negative results that shaped it (kept on the record)

The first correct kernel (v1: per-row payload pointers) ran at ~22 GB/s effective on a 1.5 TB/s GPU — gather-bound: rows of a page carry different rungs, hence different strides, so every unpack tile scattered its reads. The pre-registered "one optimization iteration" (more split parallelism) made it worse — the lever was memory layout, not occupancy. The phase-A/phase-B split above is the fix, and it was already designed into the pack format's segment lists. A second negative worth keeping: the in-kernel DCT costs ±6% — reverting pgq8 would buy zero speed.

11.7 · The signal-policy result (why no attention statistics in the format)

A standing design argument in this space: shouldn't the allocator protect the tokens that receive the most attention (as SnapKV-class methods do)? The project's policy was to allow only phase-symmetric signals in the format — things computable identically at prefill and during long generation (calibration statistics, key-intrinsic quantities, position) — because observed-attention signals exist only for prompt tokens and go stale as generation proceeds. pgq6 tested the policy with an oracle: give the allocator each token's actually realized attention mass (information unavailable at decode time), both as a distortion weight and as top-decile protection. The oracle allocation was 15% worse than the plain phase-symmetric RDO at both tested rates. The deployable signal set isn't a compromise accepted for engineering reasons — it is the better allocator, and the two positional rules (sinks, recency) capture what attention-awareness was supposed to buy.

11.8 · Integrity note: the gold-parsing correction

While cross-checking pgq6's parity numbers, the paired-bootstrap tool was found to be silently corrupting multi-answer ground truths (answers stored as a numpy-repr string ['a' 'b'] parse under literal_eval as the concatenation 'ab'). The fix was validated by recomputing per-row means for all 35 bench cells and matching every cell's official metric exactly. Every CI in this report is post-fix. One committed claim materially changed — pgq4's "significantly better than RVQ" became a tie (+0.99 [−0.62, +2.63]) — and is corrected in the study reports; the pgq5 and pgq6 headline verdicts were unaffected.

12 · Conclusion, takeaways, next steps

Conclusion

The arc set out to build a next-generation OSCAR: page-unit K quantization in which bits vary across tokens, so that uniform quantization and eviction become interior points of one format. That format now exists in its strongest form — the page-level DCT codec — and is evidenced end to end: a query-aware rotation that makes cheap scalar quantization attention-optimal (worth ~6× over OSCAR's rotation on its own); a two-level allocator (offline width profiles, online per-page λ-RDO) that spends a fixed-byte page's bits row by row; a token-axis transform that converts inter-token redundancy into allocator-visible energy compaction, breaking the entropy-coding proxy frontier at 1.0–1.5 b/c and delivering the incumbent's F1 at ~12% fewer bits on BOTH models; and a fused Triton decode kernel that serves the packed format directly — 4.25× faster than dense fp16 attention and 1.6× faster than flash SDPA at 80k context, outputs within 3·10⁻⁴ of exact, with every decode-side constant folded into one per-step query transform and a 3-bit id per row.

Takeaways

  • The basis is the battle. Rotation quality dominates quantizer quality (6–8× on proxy error). Spend calibration effort there first; everything downstream gets simpler because squared error becomes the right objective (§4 isometry).
  • Positional rules beat learned importance. The two biggest quality levers (sink escape, recency window) are pure position rules, and the observed-attention oracle lost to calibration statistics (§9.6). Cheap, deployable, phase-symmetric signals are not a compromise.
  • The ~1.5 b/c wall is real and now two-dimensional. Neither smarter width allocation nor token merging breaks the entropy-coding frontier below 1.5 b/c per original token. Below that band, buy quality with merging; don't chase EC parity.
  • Merging is a free option with a fixed-level format. Snapshotting at m∈{64,32} keeps pages in two byte classes, never hurts (the level choice simply declines to merge when bits are ample), extends the operating range down, and cuts stored rows 15–20% under rate pressure.
  • Fixed-byte pages + rung ids are enough. Variable-rate coding buys nothing at the operating point once allocation is done well — and fixed-width random access is what makes the kernel port straightforward.
  • Process earns trust. Pre-registration, held-out gates, and paired bootstraps caught two internal bugs (a stale-length decode bookkeeping bug; the gold-parsing bug) before they could contaminate conclusions — and forced an honest downgrade of one already-committed claim.

Suggestions & next steps

  1. pgq7 — the efficient implementation (in progress; plan registered). Triton FlashDecoding kernels mirroring OSCAR's architecture: rung-segmented stage-1 with the folded query and LUT dequant, positional sink/fp16 tiers, unified stage-2. Deliverables: microbenchmark vs bf16 and vs the real OSCAR kernels (pre-registered bar ≥ 2.5× vs bf16 stage-1 at 80k), then an end-to-end Qwen demo decoding from the packed cache — memory and tokens/s measured, F1 parity row-paired. The packed byte format and its bit-exact golden vectors (K1) are already built.
  2. Long-generation survival study (parked, design complete). Thinking-mode math tasks make the model consume its own compressed tokens closed-loop — the regime where quantizers die and where none of the current evidence reaches. Should run on the merged-default format once pgq7 makes decode cheap.
  3. Deferred science, ranked: phase-asymmetric signals (only worth revisiting with a better oracle construction, given §9.6); non-contiguous and cross-page merging; preferring fewer rows at equal distortion (FLOPs win); SGLang integration following OSCAR's pool/backend pattern.
