1 · Problem definition

During autoregressive decoding, a transformer keeps every past token's key and value in memory. For Qwen3-8B at 128k context this KV cache is tens of gigabytes in fp16, and each generated token must read all of it — long-context decode is memory-bandwidth-bound, not compute-bound. Compressing the cache therefore buys two things at once: capacity (longer contexts, bigger batches) and speed (less memory traffic per step).

The design constraints we imposed, following the serving reality of paged attention (vLLM/SGLang) and NVIDIA's OSCAR system:

  • Page unit. The cache is stored in fixed-size pages (64 tokens here). Every page must occupy a fixed, predictable number of bytes so the allocator stays simple and the format drops into FlashAttention-style paged kernels.
  • Decode-usable. Compression must survive being read by every future query, not just storage. No re-encoding, random access per page.
  • Kernel-implementable. Every decode-side operation must map onto a small set of GPU-kernel primitives: integer unpack, table lookup, dot product. (Python research code stores dequantized fp16 for convenience, but the format is designed so a kernel never has to.)
  • Non-uniform bits across tokens. The central bet of this project: eviction methods (SnapKV, Expected Attention, H2O) prove many tokens carry little attention mass. A page codec that can assign different bit-widths to different tokens — down to zero — contains both uniform quantization (OSCAR) and eviction as special cases, so it should never do worse than either.

Formally: for each layer ℓ and kv-head h, we need an encoder for pages of keys K ∈ ℝ64×128 whose reconstruction K̂ preserves the attention outputs future queries will compute, under a budget of b bits per coordinate per original token (all-in: payload + every bit of metadata). Values get the same treatment (held fixed to a standard 2-bit baseline in all experiments so K-side comparisons are clean).

2 · The pipeline, step by step

Five stages. Everything expensive happens offline (once per model) or at encode time (once per page); the decode path — the part that runs for every generated token — is deliberately the cheapest.

1

Calibrate: learn what queries look like

Run ~400 long prompts through the model once. For every (layer, kv-head), record the second moments of queries and keys — ΣQ, ΣK — and their means. Intuition: quantization error only matters in the directions queries actually probe. ΣQ is the map of those directions.

2

Rotate: change coordinates so error budgets make sense

Linearly transform each key into a basis (QPCA) where "one unit of quantization noise" costs the same attention damage in every coordinate — and where energy concentrates in few coordinates. Now cheap scalar quantizers become near-optimal, and importance = variance, which we can read off per coordinate.

3

Allocate: spend the page's bit budget where it hurts least

Each token in a page gets one of ≤8 pre-computed width profiles ("rungs") — e.g. 4 bits for the first 32 coordinates, 3 for the next, 0 for the tail. A rate–distortion optimizer picks each token's rung so the page exactly fills its fixed byte budget. Unimportant tokens sink to low rungs (soft pruning); no token is ever unaddressable.

4

Quantize: Lloyd-Max grids plus two safety rails

Coordinates are snapped to Gaussian-optimal levels scaled by calibration. Two protections, both derivable from position alone: the first 4 tokens (attention sinks) escape to a generous 8-bit grid, and the last 4 pages of the prompt are pinned to the top rung (the recency window — the single biggest quality lever we found).

5

Serve: fold everything into the query, decode on integer codes

At decode time the basis and all scales collapse into a single per-step transform of the query. The stored page is just integer codes + a 3-bit rung id per token; the kernel unpacks, looks up levels, dots — no per-token scales or zeros to fetch, which is OSCAR's main per-token overhead.

3 · Calibration & the right error metric

Intuition. Mean-squared error on keys is the wrong target: a large error in a direction no query ever probes is free, while a small error along a frequently-queried direction corrupts every future attention score. The fix is to weight reconstruction error by the query distribution.

From a calibration corpus we pool, per (layer, kv-head), with GQA query groups flattened:

ΣQ = E[q qᵀ],   ΣK = E[k kᵀ],   μ = E[k],   μq = E[q]

For a key error e = k − k̂, the expected squared logit error over queries is exactly a Mahalanobis norm:

Eq[(qᵀe)²] = eᵀ ΣQ e

This logit error, computed on held-out rows against each row's own real queries, is the screening proxy used everywhere below — every design choice was frozen on it before any benchmark F1 was run (pre-registration discipline).

4 · The query-aware basis (qpca_unc)

Intuition. We want coordinates that are (a) decorrelated, so scalar quantization is near-optimal, and (b) scaled so one unit of noise costs one unit of logit error everywhere. QPCA achieves this by whitening with ΣQ and then diagonalizing the query-weighted key energy.

ΣQ = U Λ Uᵀ,   W = Λ1/2Uᵀ  (query whitener)
M = W ΣK Wᵀ = V D Vᵀ  →  F = Wᵀ V  (forward),   G = F−1  (inverse)

Keys are encoded as r = (k − μ) F and reconstructed as k̂ = r̂ G + μ. In this basis the diagonal of D orders coordinates by attention-relevant energy; spectra are heavily compacted (most energy in few coordinates), which is what makes "give the tail zero bits" work. Both Σ's come from the same pooled 400-prompt statistics (_unc = uncentered, data-matched — an earlier centered variant created a calibration asymmetry that masqueraded as a quality gap).

Measured (pgq4 screening, identical quantizer swapped between bases): OSCAR's per-layer rotation is 5.9× worse logit error, r_sym is 7.4× worse. The basis is the single largest factor in the whole system.

5 · Width profiles & the page RDO

Intuition. Two facts drive the format. First, coordinates differ wildly in importance (compacted spectrum) → bit-width must vary per coordinate. Second, tokens differ in how hard they are to code and how much they matter → the per-coordinate pattern should be pickable per token. But fully free choice would need unbounded metadata. The compromise: a small ladder of ≤8 pre-computed profiles (rungs), so per-token metadata is a 3-bit id.

Building the profiles (offline, per head)

Coordinates are grouped into 4 blocks of 32. For every width w ∈ {0,2,3,4,6} and block, we measure the actual quantization distortion on the fit pool. A profile is a monotone non-increasing width tuple over blocks, e.g. (4,3,2,0); for each bits-per-token target in a fixed ladder we keep the tuple with minimum measured distortion:

profile(T) = argmint monotone, cost(t) ≤ T Σblocks b D̂b(tb)

On Llama the profile ladder can be shared per layer (sharing penalty 1.9% < 3% rule); on Qwen heads are more heterogeneous (penalty 6.2%) so profiles stay per-head — the rule was frozen, the outcome is model-dependent.

Assigning rungs (encode time, per page)

Each page must fit exactly B = b·d·64 bits including every header, rung id, and escape. Choosing each token's rung is a small constrained optimization solved with a Lagrangian:

minrung(t) Σt Dt,rung(t)  s.t.  Σt Rrung(t) ≤ B − side bits
rung(t) = argminr [ Dt,r + λ Rr ],   λ solved by bisection per page

where Dt,r is the token's actual (snap-aware) squared error under rung r — measured, not modeled, so grid overload prices itself. A greedy pass then spends any leftover bits on the best distortion-per-bit upgrades. Rung 0 (all-zero widths) reconstructs the token at the calibration mean: this is the "soft pruning" limit — the token costs ~3 bits total and still participates in attention.

6 · Grids, sinks, and the recency window

Lloyd-Max grids

Rotated coordinates are near-Gaussian, so each width uses the optimal Gaussian quantizer: unit Lloyd-Max centroids cw (the near-zero level forced to exactly 0, so rung-0 blocks and dead coordinates are exact), scaled per coordinate by the calibrated standard deviation:

r̂j = σj · cw[ argmini |rj/σj − cw[i]| ]

The top width stays a covering uniform grid (fitted step multiplier), so the highest rung bounds worst-case error instead of optimizing the average.

The sink escape

Positions 0–3 are attention sinks: enormous-norm keys that the whole sequence attends to. Quantizing them on the narrow calibrated grids clips them 3–5× past the 99.9th percentile and — because they sit in every softmax denominator — poisons all attention scores (an early hard lesson). They escape to an absolute 8-bit per-coordinate grid sized to cover the calibration sinks with margin. The trigger is pure position, so it costs zero metadata. Verified on Qwen: sink mass concentrates at positions 0–3 (median 11.7%), no displaced structural sink in 160 probes.

The recency window

pgq4's cleanest discovery: on code completion (lcc), per-token-adaptive codecs beat static ones by ~10 F1 — and the entire gap is a recency effect. Queries in code attend to the immediately preceding context. Forcing the last 4 prompt pages (256 tokens) to the top rung recovers all of it, costs +0.06–0.13 b/c, and — like the sink rule — is position-derivable with zero metadata. This "rw" window is part of the shipping config and reproduced perfectly on Qwen (lcc 56.4 → 63.4).

7 · Why this decodes fast (the fold identity)

Intuition. Everything the decoder would need to "undo" — the basis, the per-coordinate scales, the mean — is calibration-static. So instead of dequantizing every stored token every step, transform the one new query once per step and dot it directly against integer codes.

With k̂ = (s ⊙ ĉ) G + μ (codes ĉ, static scales s):

q · k̂ = ((q Gᵀ) ⊙ s) · ĉ + q·μ  =  q̃ · ĉ + consthead

The q·μ term is identical for every token in the head, and softmax is shift-invariant — it cancels. So the per-step cost is one 128×128 transform of the query per (layer, head-group), and then the kernel reads: packed codes (2–6 bits/coord as the rung dictates), a 3-bit rung id per token, and nothing else. Contrast OSCAR INT2: an fp16 scale and zero per token (32 bits/token of metadata) fetched inside the attention loop. Our per-token metadata is 3 bits — ~7× less — and there are no per-token loads besides the codes themselves. At the honest 2.13 b/c operating point, the K-side read is ~34 bytes/token versus 256 in bf16: a ~7.5× bandwidth reduction, which is the entire speed story of bandwidth-bound decode. (The pgq7 kernel port, mirroring OSCAR's Triton FlashDecoding structure, is turning this arithmetic into measured tokens/s.)

8 · Merged pages (pgq6): pruning ∪ quantization in one knob

Intuition. Width profiles vary bits per coordinate; rung-0 is per-token soft pruning. The remaining axis is the token count itself: adjacent tokens are often redundant (runs of code punctuation, boilerplate). If a 64-token page stores only m representative rows, every survivor gets more bits under the same page budget — and attention does less work. Eviction (m<n at 0 bits) and OSCAR (m=n, uniform bits) become two corners of one design space swept by a single λ.

The exactness identity

Merging is honest because of a softmax identity: attending to c identical keys k̄ with values v1..c is exactly equivalent to attending to one row (k̄, v̄, β):

Σi=1..c eq·k̄ vi = eq·k̄ + log c v̄,   v̄ = mean(vi)

So a merged row is stored as centroid key + mean value + a 6-bit run count (the bias is log c), and the +log c enters the kernel as one added scalar per row — or folds into a (d+1)-th coordinate so even unmodified FlashAttention can serve it. The only approximation is that the original keys were not exactly identical; that error is the within-run spread, and it's measurable in advance:

Σi∈run ‖ri − Q(r̄)‖² = Σi∈run ‖ri − r̄‖²  +  c·‖r̄ − Q(r̄)‖²

(the cross term vanishes over a run) — spread plus ordinary quantization error, cleanly additive, so merge levels slot into the same RDO as width rungs.

The algorithm

Per page: an adjacent-only Ward merge in the rotated basis (where unweighted distance is query-weighted distance, because the basis already absorbed ΣQ) produces nested clusterings at m ∈ {64, 32, 16}. For each level, the per-row width RDO runs under the same fixed byte budget; the page keeps whichever level achieved the least distortion. Contiguous runs mean the "cluster map" is just the run counts — no extra sideband. Sinks never merge; recency-window pages never merge; deployment pages come in two byte-size classes {S, S/2} (the 4:1 level was never chosen by the optimizer at any tested rate).

Evaluation uses the replication form (centroid repeated at member positions), which is mathematically identical to the bias form — so every existing harness measures exactly what deployment would serve.

The oracle result deserves emphasis because it settles a design argument with data: giving the allocator each token's actually realized attention mass (information that does not exist at decode time) made allocation worse than the calibration-plus-position signals. The deployable signal set isn't a compromise — it's the better allocator. This validates the phase-symmetric policy: every signal in the format is available identically at prefill and during long generation.

9.5 · Integrity note: the gold-parsing correction

While cross-checking pgq6's parity numbers, the paired-bootstrap tool was found to be silently corrupting multi-answer ground truths (a numpy-repr string, ['a' 'b'], parsed by literal_eval concatenates into 'ab'). The fix was validated by recomputing per-row means on all 35 bench cells and matching every cell's official metric exactly. Every CI in this report is post-fix; the one committed claim it materially changed (pgq4 "SIG over RVQ" → tie) is corrected in the study reports. The pgq5 and pgq6 headline verdicts were unaffected.

10 · Conclusion, takeaways, next steps

Conclusion

The arc set out to build a next-generation OSCAR: page-unit K quantization where bits vary across tokens, so uniform quantization and eviction are interior points of one format. That format now exists, is frozen, and is evidenced: a calibrated query-aware rotation (≈6× the leverage of OSCAR's), per-token width profiles chosen by an exact per-page RDO under fixed-byte pages, Gaussian-optimal grids with position-derived sink and recency protections, and token merging as an additional rung. It ties entropy coding at 2 b/c on Llama with ~7× less per-token metadata than OSCAR, transfers to Qwen3-8B with a +6 F1 margin over the strongest incumbent, degrades gracefully to 1.0 b/c (where merging buys back 28% of the error), and every decode-side operation was designed against a named GPU-kernel primitive.

Takeaways

  • The basis is the battle. Rotation quality dominates quantizer quality (6–8× on proxy). Spend calibration effort there first.
  • Positional rules beat learned importance. The two biggest quality levers (sink escape, recency window) are pure position rules; the observed-attention oracle lost to calibration statistics. Cheap, deployable, phase-symmetric signals are not a compromise.
  • The ~1.5 b/c wall is real and two-dimensional. Neither smarter width allocation nor token merging breaks the entropy-coding frontier below 1.5 b/c per original token. Below that band, buy quality with merging; don't chase EC parity.
  • Merging is a free option. It never hurts, self-disengages when unnecessary, extends the operating range down, and reduces stored rows (attention FLOPs) under rate pressure. Two page size classes suffice.
  • Fixed-byte pages + rung ids are enough. Variable-rate coding buys nothing at the operating point once allocation is done well — and fixed-width random access is what makes the kernel port straightforward.
  • Process earns trust. Pre-registration, held-out gates, and paired bootstraps caught two of our own bugs (a silent fp16 leak in decode bookkeeping; the gold-parsing bug) before they could contaminate claims — and forced an honest downgrade of one committed result.

Suggestions & next steps

  1. pgq7 — the efficient implementation (in progress, plan approved). Triton FlashDecoding-style fused kernel mirroring OSCAR's architecture (their entire INT2 path is ~6k lines of Triton — no custom CUDA needed): rung-segmented stage-1 with query folding and LUT dequant, unified stage-2, sink/fp16 tiers as a second arena. Target: ≥2.5× decode-attention speedup vs bf16 at 80k context, then an end-to-end Qwen demo with quantized-resident cache — memory and tokens/s measured, F1 parity row-paired.
  2. Long-generation survival study (parked, design complete). Thinking-mode math tasks compress the model's own tokens closed-loop — the regime where quantizers die and where none of the current evidence reaches. The parked pgq5 C0/C1 design (trace diagnostics → W* selection → closed-loop math500 with an attribution arm matrix) should run on the mrg-default format, ideally after pgq7 so decode is cheap.
  3. Deferred science, ranked: phase-asymmetric signals (prompt-window / ring-lifetime attention) — recorded, only worth revisiting with a better oracle construction given the negative result; general (non-contiguous) and cross-page merging; merged-tie preference for the FLOPs win; Qwen kernel-side per-head profile tables; SGLang integration following OSCAR's pool/backend pattern.
